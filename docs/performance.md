# 性能与包体积

## 第一批范围（2026-11-10）

保留 Go + MyGo、SQLite 持久化、内存搜索及独立插件架构。本轮先处理已确认的大量分配和重复工作：

- [x] 按配置差异应用设置。语言、外观、更新等无关修改不重建文件索引，不重启音量钩子或重复设置开机启动；Everything 连接配置与本地索引配置分开判断。
- [x] 个人规则独立发布。使用次数、别名、固定和隐藏更新只替换单条不可变规则，不再复制整个索引；文件刷新复用规则单元，避免旧扫描的规则快照覆盖最新使用记录。批量导入与重置仍使用 `UpdateProfiles`。
- [x] 搜索复用排序键，Top-K 堆保存轻量候选项，最后才生成完整结果。匹配字段保持连续，无个人别名时在命中后读取规则，减少无命中扫描的额外开销。
- [x] 索引替换复用旧 `byID` 与未变化的拼音、副标题和别名，移除重复的去重 map。
- [x] 背景图片在工作线程读取、解码和缓存，按请求代次拒绝过期结果；调节透明度、蒙版或模糊不重复解码或重新设置相同的原生材质。非 JPEG 大图按窗口与 DPI 缩小；JPEG 保留 MyGo 的 EXIF 自动转正解码，目前未降采样。
- [x] 隐藏面板取消查询，重新显示时按当前状态刷新；隐藏时索引变化不再触发插件等搜索。
- [x] 默认关闭每 2 秒一次的内存采样与 UI 更新，诊断时设置 `FL_DEBUG_MEMORY=1`。
- [x] 文件索引任务跟随配置与退出取消，取消后不写回部分扫描结果；索引配置相同时复用已有监听。原有 750ms 文件事件防抖保留。
- [x] 原始品牌图仅作生成源，发布程序携带 256px 应用图标及预处理的 48px 托盘图标，启动时不再缩放原图或计算透明边缘。

## 可复现基准

`internal/core/search/engine_bench_test.go` 使用 1,000 / 10,000 / 100,000 条固定模拟文件，25% 中文标题、75% 混合大小写英文标题，返回前 20 条。覆盖高命中英文、中文、无命中、单条规则更新和内容不变的索引替换。

```powershell
$env:CGO_ENABLED = '0'
go test ./internal/core/search -run '^$' -bench '^BenchmarkEngine$' -benchmem -benchtime=400ms -count=3
```

对照版本为优化前 `78549c7` 的源码归档，复制同一份 benchmark 文件后运行；两版顺序执行，避免构建或其他测试并行干扰。环境为 Windows amd64、Go 1.27.3、AMD Ryzen 7 5800H，默认 16 个逻辑处理器。

基准结果以每组多轮 `ns/op` 的中位数与 `B/op` 表示，不是输入到首帧延迟，也不是 P95；小样本耗时受机器负载和频率影响。原始结果保存在本地 Git 忽略的 `build/perf-audit/` 下。

| 操作 | 优化前 | 优化后 | 分配变化 |
| --- | ---: | ---: | --- |
| 1 万条英文高命中搜索 | 2.30ms | 0.56ms | 386.8KiB → 7.4KiB |
| 10 万条英文高命中搜索 | 22.86ms | 9.55ms | 3.47MiB / 150,234 次 → 7.4KiB / 32 次 |
| 10 万条中文搜索 | 15.23ms | 9.83ms | 30.5KiB → 7.4KiB |
| 10 万条无命中搜索 | 9.88ms | 9.42ms | 均为 64B / 3 次，耗时保持同量级 |
| 10 万条中更新一条使用记录 | 14.01ms | 0.37µs | 42.73MiB → 144B |
| 10 万条内容不变的索引替换 | 195.53ms | 67.09ms | 112.80MiB → 49.12MiB |

高命中英文查询分配下降约 99.8%，无变更索引替换分配下降约 56.5%。这些数据只代表上述固定数据集；不据此推算用户环境的 CPU、冷启动或总内存改善比例。

- `CGO_ENABLED=0`：`go build ./...`、`go vet ./...`、`go test ./...`、`go tool mygo vet .`、`go tool mygo i18n check .` 通过。
- `CGO_ENABLED=1`：搜索并发刷新、单条/批量个人规则更新、Top-K 排序、背景缓存/EXIF、无关设置修改和取消扫描的针对性 race 检查通过。
- Top-K 与完整排序对照覆盖大小写、兼容字符、中文/拼音、别名、固定/隐藏、多 token 和同标题的稳定排序。
- 背景缓存测试覆盖文件替换、尺寸上限、取消和 JPEG EXIF 自动转正；扫描取消测试确认数据库条目与回调不被部分结果替换。
- 隔离 MyGo 发布构建通过；资源重复生成的 SHA-256 一致，已检查生成图标。没有运行用户日常使用的启动器或访问个人配置、数据库。
- 真实材质合成、冷启动、热键首帧和用户配置下的内存占用仍未实机验收。

## 第二批：扫描、图标、结果发布与插件队列（2026-11-10）

- 文件监听消费 `FileHint.Path`，合并父子目录与重复提示，扫描受影响子树并在 SQLite 中应用差异。根目录/丢失事件提示、超过 64 个待处理目录、索引已满或增量增长超限时回退全量扫描。排除目录不触发子树刷新；目录删除、改名、重叠根、是否索引目录和 Windows junction 边界均有回归。
- 索引只运行一个扫描 worker，扫描期间的事件积累为一次后续请求，多个手动重建调用共享该次任务。配置变更取消旧扫描；关闭时释放等待者。单个调用方取消等待不会取消其他调用方共享的配置级扫描。数据库已提交后同步维护真实的内存持久化状态，避免取消恰好发生在 COMMIT 后时使后续差异比较失准。
- 图标改为 4 个固定 worker、64 个排队项和 512 项 LRU，按路径与像素尺寸去重；失败也缓存，避免每次绘制重试。队列满时不阻塞 UI，后续完成的加载触发合并重绘，仍可见的缺失图标继续请求。关闭后不接受新工作。
- 搜索第一批结果立即发布，后续完成批次按 16ms 窗口合并；结束时冲刷最后状态，未改变结果与错误的空批次不重绘。排序和合并都在 worker 中完成；状态变化而结果不变时保留列表选择与滚动。
- 插件普通全局查询增加 80ms 防抖，显式关键词和执行命令立即路由。客户端改为可取消的串行操作门，只保留最新待查请求；被替代的等待调用及时退出，不启动进程、不发送 RPC、不累计插件失败。显式动作保持独立，正在执行的 RPC 继续沿用取消、排空迟到响应和超时回收机制。

新增基准：

```powershell
go test ./internal/store -run '^$' -bench '^BenchmarkFileIndexRefresh$' -benchmem -benchtime=300ms -count=3
go test ./internal/core/search -run '^$' -bench '^BenchmarkProviderBurst$' -benchmem -benchtime=300ms -count=3
```

环境同第一批，多轮中位数如下。文件用例为 100 个目录共 10,000 个文件，比较同一版本完整扫描与刷新其中一个含 100 个文件的子树；命名信息未变化，因此不触发 SQLite 写入或内存搜索快照重建。来源用例为 20 个 provider 在同一窗口内各返回 20 条结果，保留前 20 条。

| 用例 | 全量/逐批处理 | 增量/合并处理 |
| --- | ---: | ---: |
| 文件扫描与差异检查 | 53.71ms | 5.53ms |
| 文件刷新分配 | 11.22MiB / 92,729 次 | 118.1KiB / 974 次 |
| provider 突发结果合并 | 3.37ms | 0.35ms |
| provider 合并分配 | 1.34MiB / 208 次 | 139.9KiB / 35 次 |
| provider 状态发布次数 | 20 次 | 2 次 |

真实来源分批到达时发布次数取决于完成时间；上述 20→2 不代表所有搜索都固定发布两次。条目新增或删除后仍会生成完整内存搜索快照，其成本未包含在文件扫描基准中。原始数据保存在 `build/perf-audit/second-phase-*-bench.txt`。

验证包括 `CGO_ENABLED=0` 的构建、Go vet、全部测试、MyGo vet、三语校验，以及 `CGO_ENABLED=1` 对扫描调度/关闭、目录边界、图标加载、批次发布和插件排队的针对性 race 检查。Windows 符号链接权限不可用时，测试以临时目录 junction 实际验证重解析点边界，未修改系统权限。插件隔离进程测试确认 32 个被替代的查询均未发送，最新查询和显式动作完成，进程保持复用；正在执行的旧查询取消后，迟到响应不污染新查询。

隔离未签名发布构建通过：EXE 为 18,806,784B（17.94MiB），单 EXE tar.gz 为 7,997,326B（7.63MiB）；相对第一批分别增加 28,160B 和 2,661B。新增调度与缓存逻辑未引入依赖。完整桌面环境中的冷启动、材质帧率、空闲资源及实际 Shell 图标延迟仍未实机验收。

## 第三批：可观测性与输入结果发布（2026-11-12）

- 新增本地有界异步 JSON 日志、大小/日期轮转、五分钟诊断和白名单 ZIP 导出。查询记录不含搜索原文；原始插件输出和崩溃报告默认不导出。
- 各来源、首批计算、UI 排队/应用、搜索视图构建分别计时；汇总固定直方图，区分计算完成与 UI 应用，不把后者称为真实呈现首帧。
- 跨查询合并待处理 UI 回调，百次发布在 UI 未消费时只投递一次回调并应用最新代次；避免旧结果任务积压。
- 后到结果保留用户的当前键盘选择，减少重复滚动请求；最近使用列表在后台复制、筛选和排序。
- Everything 100ms 和普通全局插件 80ms 防抖保持不变。没有用统一长防抖增加本地结果等待时间。

构建、Go vet、全量测试、MyGo vet、三语校验及相关 race 检查通过，三语深浅诊断卡片使用 `ui.NewTester` 验证并检查导出图。此轮不宣称用户环境延迟改善比例；实际输入法、材质合成、Everything 和真实插件仍需通过诊断数据验收。存储、指标口径和操作见 [日志与搜索性能诊断](diagnostics.md)。
