# 日志与搜索性能诊断

## 使用

设置 → 其他 → 日志与性能诊断：

1. 点击「开始 5 分钟诊断」。
2. 回到搜索面板，重复出现卡顿的输入、退格、中文选词、清空和方向键选择操作。
3. 点击「停止诊断」，或等待五分钟自动结束。
4. 点击「导出诊断包」保存 ZIP。启动新一轮诊断会清空上一轮内存耗时统计；已写入文件的记录按轮转策略保留。

日志和诊断包不会自动上传。默认导出排除原始插件 stderr 和崩溃报告；确有需要时勾选附加选项，分享前检查 `private/` 中的内容。

## 存储与边界

- 目录：`%LOCALAPPDATA%\FluentLauncher\logs`。
- 普通日志：`launcher.0.jsonl` 为当前文件，`.1`～`.4` 为旧文件。每个文件最大 5MiB，按大小或 UTC 日期变化轮转，最多五个。启动时清理超过七天未修改的日志，运行期间每小时清理过期备份。
- 使用标准库 `slog`，JSON 行包含时间、级别、事件、会话 ID 及该事件字段。启动事件记录版本和 Windows 版本；不引入额外日志库。
- 512 项非阻塞队列、单条最多 16KiB、32KiB 写缓冲，每秒冲刷。预留 64 个排队位置给 WARN/ERROR；队列最终满时任何级别仍可能丢弃，绝不让磁盘反压阻塞搜索输入。丢弃数和写入错误数进入诊断摘要。
- 正常退出最多等待两秒排空。强制结束或磁盘故障可能丢失尾部日志。日志初始化失败不会阻止启动，设置页提示不可用；写入失败也显示不可用状态。
- Go 运行时崩溃输出单独写入 `crash-current.log`，下次启动保留为 `crash-previous.log`，最多保留当前和上一次。启动时清理七天前的崩溃文件。该输出绕过异步队列，因此不保证 5MiB 大小上限；导出每个崩溃文件最多读取 1MiB。它不能保证捕获所有原生异常、断电或进程强制终止。

## 隐私与导出

普通日志不记录搜索文字、结果标题、启动路径、别名、剪贴板或工具输出。查询只记录长度、范围、会话内查询编号、数量和耗时。插件查询错误只记录类别，不直接落盘插件返回的任意错误文本。尚未迁移的标准库日志保留组件和事件提示、去除原始正文；明确启用的 MyGo 数字帧统计例外。

诊断包只收集本功能的轮转日志和 `summary.json`，不遍历整个数据目录，不附带配置文件、数据库、历史记录或缓存。摘要采用字段白名单：程序/Go/Windows 版本、系统架构、显示缩放、背景类型、最大结果数、索引数量、Everything 开关、插件 ID/版本/启用和运行状态、最近耗时、图标累计计数及日志健康计数。插件 ID、版本由插件清单提供；它们也会出现在导出中。

勾选原始内容后，才附加内存中各插件最后最多 8KiB 的 stderr 和上述崩溃文件。崩溃输出仍会在本机记录，可能含路径与进程信息。默认不把这些文件打入诊断包。

## 测量含义

| 事件 | 含义 |
| --- | --- |
| `query_started` | 查询编号、范围和文字长度，无原文 |
| `provider_*` | 各来源总耗时，包括已有防抖/等待，返回条数与完成/取消/失败类别 |
| `first_computed` | 查询调度到第一份可发布结果，全部无结果时为最终空结果 |
| `first_applied` | 查询调度到 UI 首次应用结果；**不等同于显示器呈现首帧** |
| `ui_queue` | 本次最新结果从投递到 UI 回调执行的等待时间 |
| `ui_apply` | UI 应用结果的时间 |
| `ui_build` | 诊断期间搜索视图构建时间，不含原生布局/GPU 呈现 |
| `query_complete` | 收集器结束或取消的耗时及发布次数，取消后外部来源可能还在退出 |
| `plugin_query` | 各插件 RPC 耗时和返回数量，无查询原文 |

五分钟诊断内保存详细事件，并按事件汇总固定直方图：1/4/8/16/32/50/100/200/500/1000/2000ms 和大于 2000ms。摘要记录次数、总时间和最大值，不把桶上界冒充精确 P95。图标命中/未命中/队列满为进程内累计计数，不是单次查询或单次诊断的比例。

默认只保留慢操作摘要：UI 阶段至少 32ms，普通搜索阶段至少 100ms，Everything/插件来源及整次查询至少 500ms。正常取消不报慢查询警告。慢事件和详细事件仍受日志队列及轮转限制。

需要进一步区分布局、绘制和原生呈现时，可在启动前设置 `MYGO_FRAME_STATS=16`，再开始五分钟诊断。该 MyGo 开关在进程初始化时读取，不能由当前设置页动态开启；环境变量未设时没有该帧统计。`FL_DEBUG_MEMORY=1` 仍仅用于现有内存采样，不代表 Windows 整个进程的内存。

## 本轮搜索改动

- 不修改 Everything 100ms、普通全局插件 80ms 防抖；本地内存来源和显式插件路由继续即时执行。
- 所有查询共享一个最新结果槽位，最多一个待处理 UI 回调；已取消查询不能覆盖新查询。仍以查询代次拒绝隐藏面板后的过期结果。
- 后续来源到达时保留用户刚用方向键选择的条目，选择 ID 和索引未变时不再重复请求滚动。
- 清空查询后的个人记录复制、最近使用筛选和排序放在工作线程，UI 只应用结果。
- 未增加“文字相同就跳过”的全局捷径，索引变化、个人规则修改和重新显示面板依然需要刷新。输入控件已有 Changed 检查。
