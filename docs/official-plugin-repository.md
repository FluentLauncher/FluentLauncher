# 官方插件独立仓库方案（待审核）

官方插件不嵌入启动器，点击安装时下载；主程序与插件独立发版。下面是仓库拆分方案，尚未创建或发布远程仓库，也尚未将现有本地示例安装入口改为联网安装。

## 仓库边界

建议公开仓库名为 `FluentLauncher-plugins`，启动器仓库保留宿主、安装器、协议校验与已安装插件管理；独立仓库负责官方插件源码、SDK、示例、打包与插件目录。

```text
FluentLauncher-plugins/
  sdk/                      # 独立 Go module；只含协议与标准库
  plugins/
    echo/                   # 最小示例
    devtools/
    clipboard/
  templates/go-plugin/      # 第三方开发模板
  docs/protocol.md          # JSON-RPC、权限说明、调试步骤
  catalog.json              # 插件目录：三语介绍、版本、下载地址、哈希
  .github/workflows/        # 编译、打包、校验并发布 Releases
```

SDK 不依赖 MyGo 和启动器宿主。现有 Go 源码从主仓库迁入，并将 `fluentlauncher/pkg/pluginsdk` 改为新仓库 SDK 的模块路径。目录清单在启动器中保留缓存，打开插件页或刷新时后台获取，避免 UI 线程网络请求。

## 安装链路

1. 启动器读取官方目录，只展示名称、说明、版本等元数据，不下载可执行文件。
2. 用户选择安装或更新某个插件，才下载该插件固定版本的 Windows x64 ZIP。
3. 校验目录规定的 SHA-256、下载大小、ZIP 路径、插件 ID、协议版本与可执行文件；安装器复用现有 staging 与替换逻辑。
4. 安装到 `%LOCALAPPDATA%\FluentLauncher\plugins\<id>`，启用后作为独立进程运行。下载或校验失败保留已有版本，并允许重试。
5. 插件更新单独提示与操作，不随主程序替换；下载期间可继续使用现有插件。

首版目录可沿用启动器的三语条目，但完整版本和下载元数据由插件仓库提供；内置条目不能成为运行包的依赖。目录签名可沿用 Ed25519 机制，并使用独立于主程序更新的密钥，审核通过后确定密钥分工。单独的 SHA-256 只能校验目录与包的一致性，不能替代可信发布源。

## 发布与开发体验

每个插件自己的 `plugin.json` 决定版本；工作流构建为 `official.echo-1.0.0-windows-amd64.zip` 等资产，压缩包根目录含 `plugin.json` 与程序。发布后更新目录中的固定下载地址和哈希，避免 `latest` 指向变化导致版本与校验值不同步。

README 给出“复制模板 → 修改 manifest → 本地运行/调试 → 打 ZIP → 启动器安装”的完整步骤。进程隔离用于故障与生命周期管理，插件仍是受信任的本地代码，不宣称安全沙箱。

待审核的是仓库拆分与 SDK 归属。审核后再迁移源码、建立远程仓库及 Actions、接入按需下载；本次主程序发布与原地更新实现不依赖这个仓库已存在。
